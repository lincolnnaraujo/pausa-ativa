## Em uma frase

A aplicação sobe inteira com um comando e mostra se o servidor está no ar; por baixo, o projeto ganhou arquitetura protegida por teste e CI em todo pull request.

## O que muda para quem usa

- **Sobe com três passos:** copiar o `.env.example` para `.env`, rodar `docker compose up -d --wait` e abrir **http://127.0.0.1:38742**. Veja o [README](../../README.md).
- A página inicial mostra **Servidor no ar**, com a versão e o horário do servidor, ou **Servidor indisponível**, com um botão para tentar de novo.
- Ainda não há jornada, lembretes nem gráficos: chegam a partir da v0.2.0.

## Critérios de aceitação

| Cenário | Verificação automática | Verificação na máquina local |
|---|---|---|
| 1. Subida do zero | Job `compose` do CI: segue o README num runner limpo | Os três serviços `healthy` em 32 s (com cache de build) |
| 2. Regra de arquitetura protegida | `RegrasDeArquiteturaTest` (R1 a R5) | Classe temporária com `@Component` no domínio fez o `./mvnw verify` falhar na R1 |
| 3. Banco indisponível | `SaudeComBancoIndisponivelTest` (container congelado com `docker pause`) | `docker compose stop postgres`: health `DOWN` em 3 s; volta a `UP` sozinho no `start`, sem reiniciar o backend |
| 4. CI | Os três jobs verdes no PR #1 | — |

## Como conferir (aceite)

1. Siga o [README](../../README.md) e abra http://127.0.0.1:38742. Deve aparecer **Servidor no ar**.
2. Derrube o banco e veja o health cair:
   ```sh
   docker compose stop postgres
   curl http://127.0.0.1:38742/actuator/health    # "status":"DOWN"
   ```
3. Religue e veja voltar sozinho:
   ```sh
   docker compose start postgres
   curl http://127.0.0.1:38742/actuator/health    # "status":"UP"
   ```
4. Confira os checks verdes no [PR #1](https://github.com/lincolnnaraujo/pausa-ativa/pull/1).

> **Na mesma máquina em que o projeto já rodou:** o volume do banco é compartilhado por qualquer cópia do projeto (`pausa-ativa_pgdata`). Se você baixar o projeto de novo em outra pasta com outra senha no `.env`, o backend não sobe, porque o banco guarda a senha da primeira subida. Use a pasta original ou apague o banco antes com `docker compose down -v`.

## Mudanças em relação à spec

Todas registradas na [spec](../specs/h1-fundacao.md).

| Mudança | Motivo |
|---|---|
| Porta padrão **38742** em vez de 80 | Pedido do usuário. Fica abaixo de 49152, porque acima disso o Windows (Hyper-V/WSL) reserva faixas que mudam a cada boot. |
| Imagem `nginx-unprivileged`, escutando na 8080 | A imagem `nginx` comum roda o processo mestre como root, e a spec exige imagens sem root |
| `socketTimeout` de 10 s no driver do Postgres | Sem ele, o health podia travar para sempre com o banco sem responder, em vez de ficar `DOWN` |
| Opções da JVM no `ENTRYPOINT`, não em `JAVA_TOOL_OPTIONS` | Essa variável faz a JVM imprimir uma linha fora do JSON a cada start |
| Fixture para cada regra de arquitetura, não só a R1 | Com os módulos vazios, as regras passariam sem verificar nada |
| Contrato com `application/json` e campos obrigatórios | O springdoc publicava `*/*` e tudo opcional |
| `/actuator/*` além do health responde 404 no nginx | Sem isso, caía no fallback da página e respondia 200 |

## Limitações conhecidas

- **Sem funcionalidade de negócio.** Esta release é só a fundação.
- **Sem proteção de branch.** Repositório privado no GitHub Free não oferece; o merge com CI verde vale por disciplina.
- **Acentos trocados no console do Windows** nas mensagens de erro do Maven (`est�`). É só exibição; os arquivos estão em UTF-8 e no CI não acontece.
- **Primeira subida demorada:** alguns minutos para baixar e montar as imagens.
- **Runner do CI:** o `ubuntu-latest` passa a ser o Ubuntu 26 a partir de 19/10/2026; a primeira execução depois disso mostra se algo mudou.
