## Em uma frase

A stack ganha o Prometheus e o Grafana: um painel pronto, sem login, mostra os lembretes por situação, o atraso dos disparos e a saúde da aplicação. Um comando faz o backup do banco e outro o restaura, iguais em qualquer terminal.

## O que muda para quem usa

- **Painel de métricas em http://127.0.0.1:38744.** Abre direto no painel **Pausa Ativa**, sem login e sem configurar nada, no intervalo "hoje". Na linha **Lembretes**: água e exercício por situação, em barras por hora; disparados, blocos montados, blocos adiados e respostas corrigidas; o atraso do disparo contra os 5 s do épico; e as abas abertas. Na linha **Aplicação**: o backend no ar ou fora, o p95 de cada operação da API contra os 200 ms, a consulta do histórico por período contra os 500 ms, a memória da JVM, a CPU, as pausas do GC, os erros da API e as conexões do banco. Em tema escuro, em português e com as cores da identidade.
- **Backup com um comando:** `docker compose run --rm backup` grava `pausa-ativa-<data e hora>.dump` na pasta `backups` (ou na do `BACKUP_DIR`) e diz quantas jornadas o backup tem. Com o banco parado, recusa com uma mensagem clara e não deixa arquivo.
- **Restauração protegida:** `docker compose run --rm restauracao <arquivo>` exige o backend parado, pede para digitar `RESTAURAR`, guarda antes um backup do banco atual e restaura numa transação só: ou volta tudo, ou nada muda.
- **A aplicação não depende do painel.** Com o Prometheus ou o Grafana parado, ela segue igual.
- **Parada limpa.** Com uma aba aberta, o `docker compose stop backend` agora para em menos de 1 s; antes, o backend era morto à força.
- **Apresentação.** A [jornada de um dia em capturas de tela](../apresentacao.md), do perfil físico ao painel de métricas.

## Como conferir (aceite)

1. Suba a demonstração com o banco limpo:
   ```sh
   docker compose -f docker-compose.yml -f docker-compose.demo.yml down -v
   docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --build --wait
   ```
2. Abra **http://127.0.0.1:38745** no Chrome: o painel **Pausa Ativa** abre sem login, ainda vazio.
3. Abra **http://127.0.0.1:38743**, preencha o perfil, clique em **Iniciar dia** e responda alguns lembretes (um por minuto). Corrija um na lista e finalize o dia.
4. Volte ao painel: em até 30 s, as barras mostram o que você fez, com a correção em "Respostas corrigidas".
5. Faça um backup:
   ```sh
   docker compose -f docker-compose.yml -f docker-compose.demo.yml run --rm backup
   ```
6. Apague tudo e restaure num banco novo, digitando `RESTAURAR` quando for pedido (troque o nome pelo do passo 5):
   ```sh
   docker compose -f docker-compose.yml -f docker-compose.demo.yml down -v
   docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --wait postgres
   docker compose -f docker-compose.yml -f docker-compose.demo.yml run --rm restauracao pausa-ativa-AAAA-MM-DD-HHMMSS.dump
   docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --wait
   ```
   Na aba **Histórico**, o dia de hoje e os dias de exemplo voltaram.
7. Pare o banco e tente o backup: a mensagem pede para subir a aplicação, e nenhum arquivo novo aparece em `backups`.
   ```sh
   docker compose -f docker-compose.yml -f docker-compose.demo.yml stop postgres
   docker compose -f docker-compose.yml -f docker-compose.demo.yml run --rm backup
   ```
8. Ao terminar, apague a demonstração com `down -v`.
9. Confira os checks verdes no [PR #8](https://github.com/lincolnnaraujo/pausa-ativa/pull/8).

## Mudanças em relação à spec

Todas registradas na [spec](../specs/h5-metricas-e-backup.md).

| Mudança | Motivo |
|---|---|
| Grafana com 512 MB, e não 256 | Com 256 MB, o Grafana 13 vivia no limite, e o kernel reclamava memória o tempo todo (T3) |
| Mínimo de 1 ms no histograma do `http.server.requests` | A chave vale por prefixo e também pega o `http.server.requests.active`, cujo mínimo padrão (2 min) passava do teto de 5 s (T1) |
| Séries zeradas na subida | O Micrometer só cria um medidor no primeiro evento, que o `increase()` do painel perdia (T3) |
| Barras medindo o intervalo que começa no seu instante | Sem isso, a hora corrente só aparecia quando terminasse (T3) |
| Restauração recriando o esquema a partir do SQL gerado antes | O `--clean` deixaria sobrar uma tabela de versão mais nova; e um arquivo corrompido no meio não pode confirmar a parte que chegou (T4) |
| O backend fecha as conexões SSE ao parar | Com uma aba aberta, o `stop` acabava em SIGKILL (código 137), e a restauração pede essa parada. O problema existia desde a v0.2.0 (T5) |
| A confirmação da restauração só olha as letras | O pipe do PowerShell 5.1 manda um BOM e `\r\n`, e `RESTAURAR` era recusado (T5) |
| Consulta do histórico em três números, Dia, Semana e Mês | Com um período só, a barra ocupava o painel e o Grafana escondia o nome do período (T5) |
| Apresentação com capturas de tela | Pedido do usuário na T6 |

## Limitações conhecidas

- **Sem alertas** (fora do escopo da H5): o painel mostra, mas não avisa.
- **Taxa de sucesso só no Histórico** (D5): o painel conta a resposta original, e a correção aparece à parte.
- **Backup manual** (D7): o README sugere um por semana e uma cópia fora do computador.
- **Os números do painel recomeçam a cada subida do backend.** O Prometheus soma os trechos, mas um evento entre a última coleta e a parada pode não aparecer.
- **Logs fora do Grafana:** continuam em JSON no `docker compose logs`.
- **Sem link para o painel na tela da aplicação** (D12): o endereço está no README.
- Continuam valendo as limitações da [v0.4.0](v0.4.0.md#limitações-conhecidas), menos a última: o painel das métricas chegou nesta versão.
